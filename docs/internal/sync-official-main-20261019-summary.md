## 模型与组件要点

- **DeepSeek-V4/V4.1**：重点是 mHC 小 batch 算子、MXFP8 与稀疏 prefill、BCG 长上下文 replay、DSpark draft metadata、V4.1 多模态输入与 ROCm 路径。最新冻结点包含 AMD mHC fused post+pre buffer cache 有界化，避免无限缓存增长。
- **GLM/KDA、Qwen/QSA**：推进混合线性 attention 的 prefill graph、MTP verify、DCP 和稀疏 indexer，修复低并发 DP、状态提交边界与图 replay 元数据一致性。
- **Kimi、MiniMax、MiMo 与新模型**：涉及模型路由、量化/专家布局、上下文并行、多模态预处理和 draft 能力；逐项见下面模型索引，避免把某一模型的路径变化泛化为全模型支持。
- **KV/HiCache/内存**：host pool 显式几何与 buffer descriptor、draft KV 地址空间、统一内存、混合 Mamba 状态、生命周期及传输 drain/abort 是主要接口变化。内部 HCU page-major buffer、layer split、GLM KDA 需逐项适配。
- **服务与调度**：批量 detokenizer 分发、长 prompt 编码、模板缓存、Responses token budget、watermark 密钥脱敏、PD host-receive 阈值及 bootstrap 共识均影响运行行为。
- **升级约束**：官方 Python 下限提升至 3.11；`--attn-dp-size`、host-receive threshold 与 cache 默认行为变更需核对。HCU 构建保留独立依赖约束，实际兼容性以本次运行验证为准。

以上是代码/提交范围的更新归纳。官方发布中的速度数字依赖其硬件、模型和负载，不代表本次 HCU TP8 已测得同等收益。
