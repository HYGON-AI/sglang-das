1. 一眼看懂总链路

官方 PR CI 形态：触发、门禁、真实 runner、容器、测试分片、最终 check
PR

pull_request

opened / synchronize / reopened / labeled / ready_for_review

check

check-changes

判断是否改到 DCU 相关路径，并决定跑 Stage A/B。

gate

call-gate

调用 pr-gate.yml，对齐官方 run-ci label 门禁。

config

validate-config

检查 DCU_CI_RUNNER_LABEL 和 DCU_CI_IMAGE。

runner

self-hosted DCU

GitHub 按 runner label 把 job 调度到 DCU 节点。

test

Stage A/B matrix

容器内执行 run_suite.py --hw dcu，Stage B 两分片。

finish

PR Test (DCU) finish

聚合所有依赖 job，作为最终 required check 候选。

2. Runner 和仓库变量

runner 注册在机器侧，仓库只消费 label
机器侧 在 DCU 节点安装 GitHub Actions self-hosted runner，并给它打 label，例如 nmz26-dcu-sglang。
GitHub 侧 repo/org 能看到 runner online，workflow 用 runs-on 匹配 label。
仓库代码 没有“注册 runner”的逻辑，只在 workflow 中读取 DCU_CI_RUNNER_LABEL。
失败表现 runner offline 或 label 不匹配时，Stage A/B job 会 queued，不会进入容器。

必须配置

DCU_CI_RUNNER_LABEL 选择 DCU runner；DCU_CI_IMAGE 选择 DTK/DCU 容器镜像。

调试可选

DCU_CI_SKIP_PULL=1 避免重复拉镜像；DCU_CI_SKIP_SGLANG_BUILD=1 复用镜像内依赖。

合官方时注意 官方默认路径建议只强依赖 runner label 和 image。skip 类变量只作为测试仓库调试能力，避免污染官方长期默认策略。

3. 容器执行逻辑

workflow 到 DCU 容器内测试的三段式脚本

dcu_ci_start_container.sh

启动 DCU 容器，挂载 checkout 到 /sglang-checkout，挂载 /dev/kfd、/dev/dri、模型目录和 cache。

dcu_ci_install_dependency.sh

安装 DCU 依赖和 editable SGLang。测试仓库可通过 DCU_CI_SKIP_SGLANG_BUILD 跳过 build。

dcu_ci_exec.sh

在容器里执行 run_suite.py，注入 CI marker、本地模型路径、PYTHONPATH=/sglang-checkout/python。

4. 测试注册和分片

register_dcu_ci 是标记，run_suite.py 才是执行入口
1

测试文件声明注册

在测试文件顶层写 register_dcu_ci(est_time=10, suite="stage-b-test-1-gpu-small-dcu")。

2

ci_register.py 静态解析

通过 AST 收集 register_dcu_ci，拿到 backend、suite、est_time、nightly、disabled。

3

run_suite.py 过滤 suite

根据 --hw dcu、--suite、--include-file 选出要跑的文件。

4

Stage B 自动分片

通过 --auto-partition-id 和 --auto-partition-size 让 matrix 两个 job 各跑一片。

5

unittest/pytest 执行

最终由 suite runner 执行文件，失败会传递到 Stage job，再由 finish job 聚合。

6. 合入官方仓库路线

先合框架，再扩用例，风险最小
1

从官方最新 main 起分支

只带 DCU PR CI 框架和最小 flow smoke，不夹带大规模用例扩容。

2

官方仓库配置变量和 runner

配置 DCU_CI_RUNNER_LABEL、DCU_CI_IMAGE，确认 self-hosted runner online。

3

开 PR 并加 run-ci

验证 PR 自动触发、gate、Stage A/B、finish 全链路。

4

把 PR Test (DCU) finish 设为 required 候选

确保 required check 名称固定，后续扩测试不改变对外信号。

5

后续 PR 扩大测试集

按 interface/unit、kernel、OpenAI server、小模型、embedding/reranker、Qwen server、VLM/LoRA/HiCache/Spec 逐步推进。

7. 代码地图

同事接手时优先阅读这些文件
.github/workflows/pr-test-dcu.yml DCU PR CI 主 workflow：触发、gate、config、Stage A/B、finish 全在这里。
.github/workflows/pr-gate.yml 官方风格 PR gate，被 DCU workflow 通过 workflow_call 调用。
scripts/ci/dcu/dcu_ci_start_container.sh 启动 DCU 容器，挂载设备、模型和 checkout。
scripts/ci/dcu/dcu_ci_install_dependency.sh 容器内依赖安装逻辑，支持测试仓库 skip build。
scripts/ci/dcu/dcu_ci_exec.sh 容器内命令执行入口，注入 CI marker、本地模型路径和 PYTHONPATH。
python/sglang/test/ci/ci_register.py 新增 HWBackend.DCU 和 register_dcu_ci，通过 AST 收集注册信息。
test/run_suite.py suite 过滤、disabled 跳过、include-file 收缩、自动分片、执行测试。
test/registered/dcu/** DCU 专属测试和当前 flow smoke；后续真实用例扩容主要在这里推进。
docs/dcu-pr-ci-integration-handoff.md 当前状态、验证命令、GitHub 成功 run、交接说明。
